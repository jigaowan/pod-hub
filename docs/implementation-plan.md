# Pod Hub 实现计划

## 目标

按照当前 `docs/` 文档约束，将 MVP 拆成可连续交付的四个阶段，并保证每阶段都有明确的可运行结果。

## 阶段拆分

### 第 1 阶段：工程基础与数据层

- 建立 `FastAPI` + `SQLAlchemy` + `Jinja2` 工程骨架。
- 完成环境变量配置校验、日志初始化、SQLite 初始化。
- 建立 `channels`、`episodes`、`sync_runs`、`app_settings` 四张核心表。
- 完成仓储层和基础 view model。

当前状态：已完成。

### 第 2 阶段：同步主链路

- 封装 `yt-dlp` 调用，统一处理频道解析、列表提取、音频下载。
- 实现本地媒体存储发布规则：`_tmp` 下载、正式目录原子发布。
- 完成首次接入、定时轮询、新节目优先、历史补抓、失败重试的同步服务。
- 实现全局串行协调器，避免调度重入。

当前状态：已完成首版实现，后续可继续补更细粒度重试与超时测试。

### 第 3 阶段：后台页面与公开接口

- 后台提供频道列表、新增频道、频道详情三页。
- 提供 `/feeds/{channel_slug}.xml` RSS 输出。
- 提供 `/media/{episode_id}.mp3` 音频访问。
- 明确页面只展示数据库状态，不暴露手动同步入口。

当前状态：已完成首版实现。

### 第 4 阶段：交付与验证

- 接入 `APScheduler` 周期调度。
- 提供 Docker 与 docker-compose 运行方式。
- 增加基础单元测试和离线语法校验。
- 后续再补集成测试、真实 `yt-dlp` 冒烟测试和部署文档。

当前状态：本轮已完成基础配置，测试仍以离线单元测试为主。

## 后续建议

### 近期优先补齐

- 为 `yt-dlp` 调用增加更严格的 stdout/stderr 解析与超时覆盖测试。
- 为同步流程增加基于 fake downloader 的集成测试。
- 增加数据库迁移工具而不是仅依赖 `create_all`。
- 为 RSS 增补 iTunes 常见字段，提升播客客户端兼容性。

### 暂不扩展

- 多用户、鉴权、手动同步、编辑删除频道、JSON 管理 API。
- 外部任务队列、并发 worker、对象存储。
- AI 摘要、转写与音频增强。
